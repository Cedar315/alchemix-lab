## 1. 产品概述

**AlcheMix Lab / 便利店调酒助手** 是一个移动端优先的 Web App，面向不会专业调酒、但想用便利店或家里现有饮料调出好喝微醺饮品的用户。

用户可以用常见材料，例如啤酒、烧酒、金酒、苏打水、乌龙茶、养乐多、水溶 C、果汁、椰奶饮料等，得到简单、低门槛、可复刻的调酒方案。

### 当前产品定位

当前版本 **不做 AI Agent 聊天助手**。  
Assistant 页面不是聊天机器人，而是一个工具型首页，提供三个明确入口：

- 根据手边材料生成可做酒卡
- 根据心情生成推荐酒卡
- 随机一杯盲盒

当前 MVP 暂不接 AI 主流程。后续可以把 AI 作为辅助能力层，用于本地库缺失时生成候选资料、辅助解释风味或给配方命名；但用户主流程不是和 AI 聊天，而是通过按钮、酒卡、记录和推荐系统完成任务。

### 产品核心理念

1. **低门槛**  
   不要求用户有摇壶、滤冰器、苦精、专业酒杯等酒吧设备。

2. **好喝**  
   通过酸甜平衡、酒感控制、气泡保留、奶感/茶感/果香搭配，让新手也能做出稳定口味。

3. **好买**  
   数据库优先覆盖便利店、超市、罗森、7-Eleven、全家等常见饮品。

4. **可复刻**  
   每杯酒给出清楚比例、材料、步骤、推荐冰量、推荐杯型和注意事项。

5. **可记录**  
   用户喝完后可以记录评分、口味感受、真实评价，并沉淀成自己的调酒日记和口味画像。

## 2. 目标用户

### 2.1 宿舍 / 租房青年

想在家低成本喝一点微醺，不想买一整套酒吧工具，也不想研究复杂配方。

### 2.2 聚会组织者

需要快速做出多人能接受、材料便宜、视觉好看、失败率低的酒。

### 2.3 便利店饮料探索者

喜欢尝试网红喝法，比如烧酒 + 养乐多、啤酒 + 西柚汽水、野格 + 功能饮料等。

### 2.4 家里有剩酒的人

家里有半瓶金酒、伏特加、威士忌、朗姆等，但不知道还能怎么搭配日常饮料。

## 3. 核心用户场景

### 场景 A：根据手边材料推荐

用户打开冰箱，发现有金酒、苏打水、柠檬和苹果汁。  
他在 App 中输入或选择这些材料，系统生成可以直接做的酒卡，例如：

- 苹果金酒苏打
- 柠檬金汤力
- 清爽苹果 Highball

每张酒卡展示材料、比例、做法、风味特点和适合人群。

### 场景 B：经典鸡尾酒改良

用户想喝内格罗尼，但觉得原版太苦、太烈，也买不到金巴利和甜味美思。  
他选择：

- 降低酒感
- 少苦一点
- 便利店版

系统基于本地规则和酒单数据给出更适合新手的改良版本，例如用低比例金酒、橙味饮料、苏打水或草本饮料保留原版灵魂。

### 场景 C：按心情和口味找酒

用户下班后想喝一杯放松、清爽、低酒感、带气泡的酒。  
系统根据心情标签、口味画像和推荐算法，推荐低酒精、果香、气泡感强的酒卡。

### 场景 D：喝完记录

用户喝完一杯西柚金汤力后，记录：

- 总体评分 4.5
- 清爽度 5
- 果香 4
- 酒感 2
- 真实评价：西柚味明显，酒感不重，适合晚上随便喝

这些记录会进入调酒日历和口味画像。

## 4. MVP 功能范围

### P0 必做功能

1. **添加材料 / 实验室**
   - 选择酒类和非酒精配料
   - 显示当前总量
   - 基于本地规则输出风味分析和小白建议

2. **便利店调酒推荐**
   - 根据材料推荐可做酒卡
   - 支持便利店常见饮料和常见基酒

3. **Inspiration 探索页**
   - 便利店特调
   - 经典鸡尾酒
   - 双列酒卡瀑布流

4. **经典鸡尾酒改良**
   - 原始配方
   - 调整方向
   - 定制版结果

5. **记录一杯 / 已喝记录**
   - 评分
   - 多维口味打分
   - 收藏
   - 星标
   - 真实评价
   - 同步调酒日历

6. **My 档案中心**
   - 调酒日历
   - 最近喝过
   - 我的收藏
   - 口味画像

7. **本地数据库优先**
   - 配料、饮料、果汁、酒类、经典配方优先从本地 seed 数据读取
   - 本地没有时先提示“暂未收录”，AI 辅助补全放到后续版本

8. **口味画像和推荐算法**
   - 根据搜索、点击、实验、收藏、已喝评分生成用户画像
   - 用多维风味向量计算酒卡匹配度
   - 让用户评分越多，推荐越准确

### P1 后续增强

- Supabase Auth 真注册登录
- drink_logs 真正写入 Supabase
- 更完整的搜索行为记录
- 口味画像算法落地
- 推荐排序优化
- 可选接入 MiniMax / OpenAI 等 AI 服务
- AI 辅助风味解释和配方命名

### P2 / 2.0 暂不做

- 拍照识别 / OCR
- 条形码扫描
- 社区 Feed
- 用户互相关注
- App Store 原生 App

## 5. 页面结构

App 使用移动端优先布局，桌面端保持手机容器效果。

### Assistant

当前是工具型首页，不是 AI Agent 聊天页。

首页推荐入口：

- 根据材料生成酒卡
- 心情实验室
- 随机一杯盲盒

推荐逻辑：

- 优先使用本地酒单和配料数据库
- 根据材料匹配可做配方
- 根据心情标签映射口味方向
- 根据口味画像排序候选酒卡
- 后续在本地无结果时，可调用 AI 生成候选补充方案，并进入审核流程

### Lab

酒精实验室：

- 添加材料
- 烧杯视觉
- Stir / Shake
- 风味分析
- 保存 / 记录一杯

### Inspiration

探索页：

- 便利店特调
- 经典鸡尾酒
- 搜索
- 分类标签
- 双列酒卡

### My

个人档案：

- 登录 / 注册入口
- 调酒日历
- 最近喝过
- 我的收藏
- 我的高分酒
- 口味画像

## 6. 酒精安全规则

1. **不鼓励过量饮酒**  
   文案避免“多喝”“灌醉”“挑战酒量”等表达。

2. **高咖啡因 + 酒精提示**  
   功能饮料、咖啡类饮料和酒精混合时，应提示风险。

3. **低酒感模式保护**  
   当用户选择低酒感、新手友好时，应降低烈酒用量，优先推荐啤酒、烧酒、梅酒、气泡饮或长饮结构。

4. **ABV 估算**  
   配方尽量显示大致酒精度范围，让用户知道强弱。

5. **不面向未成年人**  
   后续正式上线需要加入年龄确认。

## 7. 产品成功标准

MVP 成功不在于 AI 多聪明，而在于用户能不能完成以下闭环：

1. 找到一杯想喝的酒
2. 看懂材料和比例
3. 能用便利店材料做出来
4. 喝完能记录真实反馈
5. 下次系统能更懂他的口味

## 8. 算法在产品中的作用

口味画像和推荐算法是 AlcheMix Lab 的长期核心能力。

算法负责：

- 把用户搜索、点击、实验、收藏、已喝记录转成口味偏好
- 判断用户更喜欢清爽、果香、低酒感、奶感、茶感还是苦甜结构
- 给酒卡排序
- 避免总是推荐同一种酒
- 给用户解释“为什么推荐这杯”

算法不负责：

- 编造事实数据
- 替用户写真实评价
- 替代安全规则
- 直接修改数据库

推荐方式采用轻量推荐系统：

- 内容推荐：用酒卡风味向量匹配用户口味画像
- 混合推荐：综合搜索、点击、实验、收藏和已喝记录
- 时间衰减：最近行为比很久以前更重要
- 探索机制：大部分推荐熟悉口味，少量推荐相邻新口味
