版本：悬浮助手方案 v1；更新：2026-09-14；状态：主路径已接入，本文仍作为需求及验收基准。当前实现与限制见 [文档导航](README.md)。

本文参考项目方提供的《AI虚拟角色产品文档》中“产品概述—功能交互—AI生成内容”的组织方式，描述调酒助手自身的业务规则。角色陪伴、主动开场、亲密度、语音及图片视频输入不纳入本期。

## 一、产品概述

### 1、产品定位

在现有调酒工作流中提供按需使用的 AI 助手。当用户不知道功能位置，或选定酒款后遇到缺料、制作问题时，通过自然语言求助，获得功能入口或有依据的解释。

首页选酒、酒精实验室、经典酒及便利店调酒仍是主要使用路径。助手不要求用户重新填写一套选酒表单，也不建立第二套配方推荐逻辑。

### 2、目标用户与核心价值

目标用户是使用现有流程的成年调酒初学者。需求来自项目方场景判断，尚未通过用户访谈和线上数据验证；以下价值是待验证目标。

| 用户场景 | 当前困难 | 助手提供的价值 | 成功结果 |
| --- | --- | --- | --- |
| 想了解橙汁与伏特加的搭配 | 不知道实验室能分析搭配 | 识别材料，提供实验室入口 | 到达带有这些材料的实验室并继续操作 |
| 想查手边材料能做哪些酒 | 不知道从哪查已有配方 | 复用库内匹配，提供具体酒单 | 进入符合需求的真实详情 |
| 选好一杯却缺材料 | 不知道能否替换或在哪替换 | 保留当前酒，提供功能入口或知识依据 | 理解替换条件及下一步 |
| 制作过程中遇到问题 | 不理解步骤或异常原因 | 结合实际情况解释，必要时追问 | 得到适用的处理说明或明确知识边界 |

### 3、产品边界

配方身份、材料、匹配排序和页面链接来自业务数据；AI 负责理解问题和组织受证据约束的回答。首版使用一个编排器，不引入 sub-agent。助手不自动记酒、评分、扣库存，也不把生成配方当成库内结果。

缺料时保留当前酒的目标，不承诺替换后风味完全相同或仍满足经典配方定义。具体决策规则统一维护在 [Agent 方案](cocktail-agent-plan.md)。

## 二、产品功能与界面交互

### 1、入口与主要操作

| 功能 | 用户操作 | 页面反馈 |
| --- | --- | --- |
| 打开助手 | 在经典详情、便利店详情或实验室点击圆形按钮 | 展开问答面板，显示当前酒或实验室背景；不主动发送开场消息 |
| 输入问题 | 自由输入并发送 | 展示用户消息和处理状态；不放预设问题按钮 |
| 阅读回答 | 查看文字、依据或酒单卡片 | 将解释与可点击动作分开展示 |
| 使用已有功能 | 点击定位、跳转或实验室入口 | 执行校验通过的动作；跨页交接后折叠助手 |
| 处理已有编辑 | 实验室已有内容时选择保留或替换 | 只有明确选择替换才覆盖 |
| 继续或切换任务 | 折叠重开，或切换另一杯酒 | 同任务保留对话；跨杯更新背景并隔离旧事实 |

首页、浏览列表和我的记录不显示悬浮入口。移动端抽屉默认约占屏幕三分之二，可展开、折叠；电脑预览同样在手机页面容器内使用底部聊天抽屉。字体、色彩、间距及按钮继承现有产品体系。第二页与子页面的视觉统一仍待实施。

详细操作、异常反馈和完整流程图见 [交互规范](preparation-agent.md)。

## 三、AI生成内容

### 1、内容生成流程

用户输入 → 读取页面与对话背景 → 识别意图及对话行为 → 判断已有功能是否支持 → 调用工作流或检索知识 → 校验结果与依据 → 展示回答及有效操作入口。

生成内容的目标是让用户知道“下一步怎么做”。可由工作流完成的任务交回对应功能；纯知识回答无需强制跳转。

### 2、对话策略设置

#### 1）意图识别与回复策略

| 意图分类 | 意图说明 | 用户表达举例 | 回复内容特征与策略 |
| --- | --- | --- | --- |
| 功能操作咨询 | 不知道功能位置或使用方法 | “在哪里改成便利店版本？” | 查当前页面能力，同页定位；跨页提供有效入口 |
| 材料搭配探索 | 想了解材料混合后的风味 | “橙汁和伏特加配起来什么味道？” | 提供带材料的实验室入口，分析交由已有流程，不补用量 |
| 库内配方查找 | 想知道已有材料能做什么 | “这些材料可以做什么酒？” | 复用匹配与 App 酒库卡片，点击展开酒单；仅两类都有候选且未表偏好时询问类别；最多三杯 |
| 指定酒单查找 | 想查看明确的一杯酒 | “打开玛格丽特的配方” | 查真实酒单并提供具体详情，不重复问类别 |
| 当前配方缺料 | 选定酒款但缺少材料 | “这杯没有橙味利口酒怎么办？” | 先确认缺什么，再问手边有什么；先查站内酒库和资料，不足再联网；给替代选项、差异与来源链接，保留现有快捷入口 |
| 制作步骤咨询 | 不理解具体操作 | “这杯应该放多少冰？” | 结合当前配方检索；只有影响回答时才追问器具或实际情况 |
| 制作问题排查 | 实际操作后出现问题 | “已经混好了，为什么分层？” | 先问实际材料和操作，再查站内资料，不足再联网；给可能原因、补救建议和来源链接 |
| 知识解释 | 希望理解技法或材料知识 | “为什么要过滤？” | 检索后回答并展示依据，不要求先选酒 |
| 范围外或不明确 | 超出服务范围或缺少必要指代 | “帮我写简历”／孤立的“300” | 分别说明范围或追问，不强行转为选酒 |

识别顺序、工具选择和候选规则见 [Agent 方案](cocktail-agent-plan.md)；本表为产品概览，不是新增 API 枚举。

#### 2）多轮对话处理

| 对话情况 | 举例 | 处理要求 |
| --- | --- | --- |
| 回答追问 | 询问缺什么后，用户说“橙汁” | 补充当前任务事实，不重新推荐酒 |
| 纠正信息 | “说错了，是30毫升” | 指代明确才更新对应事实，否则追问材料名称 |
| 结果反馈 | “还是太甜了” | 延续当前问题；不能视为用户已执行未确认的建议 |
| 取消任务 | “算了，先不改了” | 停止处理，取消待执行动作 |
| 切换酒款 | 打开另一杯详情 | 开启新任务，结束旧对话，不沿用旧杯实际情况 |

混合问题保留各项需求，例如选酒与知识问题同时出现时，不能因提供跳转而遗漏知识部分。

### 3、回复内容要求

操作类展示下一步及有效按钮；选酒类沿用 App 酒库展示方式，显示酒名、匹配原因、必要缺料提示，点击展开查看；知识类先回答，再说明适用范围及来源链接。缺料依次确认缺少的材料、手边可用材料；故障排查先确认实际材料和操作。追问每次只问一个必要问题，已由用户说明或上下文确认的信息不重复询问，页面配方不能视为用户实际操作。

语言简洁、自然、适合新手，不用无关寒暄或拟人动作延长回答。固定异常话术由界面状态选择，知识、推荐理由与替换说明基于真实结果生成。完整模板及固定话术统一见 [回复规范](agent-response-guidelines.md)。

### 4、知识库调用与异常处理

制作知识、缺料解释和故障排查根据资料回答；页面导航与配方匹配不靠 RAG 生成。资料不足时说明不能确定，查询失败时说明未完成，不能把两种情况都写成“没有答案”。知识分类、来源、触发条件和维护规则见 [RAG 文档](rag-setup.md)。

### 2026-09-17 确认的回复流程

缺料：缺什么 → 手边有哪些材料 → 站内酒库及知识资料 → 证据不足时联网 → 替代建议、差异、来源链接与现有快捷入口。不得在用户补充可用材料之前先推荐替代；用户已说清的信息跳过追问。

搭配风味问题交给实验室，提供带入材料的入口；已有材料查酒展示真实酒库结果并点击展开。制作步骤和知识解释缺必要信息才追问，先站内后联网。实际太甜、分层等故障先了解实际材料和操作再给建议。功能咨询、指定酒单查找、取消和切换话题沿用已有规则。

## 四、验收与产品指标

验收覆盖意图识别、正确交接、跨杯隔离、覆盖确认、引用忠实性和失败恢复。错误跳转、未经确认覆盖、旧事实污染和无依据精确比例是发布阻断项。

衡量功能到达率、工作流完成率、求助解决率、无效追问率、引用忠实率、延迟和任务成本；定义、样本要求及历史证据统一见 [验证文档](agent-verification.md)。当前没有业务提升、成本降低或完整人工验收的实测结论；代码与分层验证记录见 [实现说明](companion-implementation.md)。


## 2026-09-15 确认的行为修订

### 功能目标与场景

让用户在当前酒遇到操作或知识问题时获得连续对话帮助；未覆盖的问答知识通过联网形成待审核条目。自创配方归用户收藏，不进入公共知识库。

### 处理策略与展示内容

发送后立即显示右侧用户消息并清空输入，左侧显示输入中及最终回复；失败保留消息并可重试。标题使用实际酒名，实验室有结果时使用结果名称。手机与电脑预览都在手机容器内展开，移除历史任务入口。同杯收起保留聊天，离页、换杯、刷新结束聊天。

发现页所有重新进入路径显示“从一杯开始”，包括推荐酒详情返回；旧推荐只在用户点击“继续看上次选出的酒”时展示。酒卡、酒单与助手使用一致身份；缺失配方不默认显示另一杯。未核实用量不生成占位配方。

“找类似的酒”按现有库的口味标签和材料交集提供最多三杯，说明依据，不声称用户材料齐全。两类均有候选且无偏好时才询问类别。

### 异常与验收

后台网络、索引未就绪不等同知识缺口。联网只用于调酒知识证据不足，不用于修复内部链接或操作问题。详情见[知识闭环](knowledge-learning.md)。新增规则以本节为准；既往测试结果仍保留原日期，不代表本轮已通过。
