# AI 回复内容与话术规范

更新：2026-09-14；状态：产品展示与话术规范，v2 已接入主路径；完整措辞仍以运行状态和证据为准。意图和工具选择以 [Agent 方案](cocktail-agent-plan.md) 为准，本文件只定义用户看到的内容。

## 一、回复目标与表达要求

让用户理解当前问题和下一步操作。先给与问题直接相关的内容，再补必要条件和依据。面向新手使用短句，解释必要术语，不增加角色扮演、拟人动作或主动开场消息。

按钮只能来自校验通过的页面能力或真实配方。纯回答不强行附按钮。用户未点击前不能写“已为你打开”；没有成功检索不能写“已查阅资料”。

## 二、动态内容展示模板

花括号表示业务数据或有证据的生成内容，不是固定答案、API 字段或允许模型猜测的占位信息。只有所需值存在且校验通过才显示对应内容；不得将未填占位符展示给用户。

| 回复类型 | 触发场景 | 展示顺序／模板 | 动态内容依据 | 异常规则 |
| --- | --- | --- | --- | --- |
| 操作咨询 | 用户不知道功能位置 | “可以在{功能名称}中{操作目的}。”＋按钮“{定位或打开功能}” | 真实页面能力与按钮标签 | 无有效目标则说明不可用，不造入口 |
| 搭配探索 | 用户询问材料混合风味 | “可以把{已确认材料}带到实验室查看搭配。”＋按钮“到实验室查看搭配” | 用户材料及有效实验室动作 | 不生成毫升数；已在实验室则定位已有操作 |
| 库内配方查找 | 已获得有效候选 | 最多三张卡：{酒名}、{匹配原因}、{缺料提示，仅必要时}、按钮“查看{酒名}” | 匹配结果、真实材料、详情身份 | 不把缺料候选写成现在就能做 |
| 指定酒单 | 用户指定名称且已查到 | “找到{酒名}的酒单。”＋按钮“查看{酒名}” | 真实配方查找结果 | 未找到或名称多义时不猜链接 |
| 缺料：已有功能支持 | 已选酒，缺料项明确 | “可以先在{替换功能名称}中查看{缺料项}的调整选项。”＋有效按钮 | 当前酒及已注册替换能力 | 不声称替换已执行，不切换为另一杯 |
| 缺料：需要知识解释 | 已有知识支持替代建议 | {建议选项} → {适用条件} → {风味差异或限制} → {来源} | 检索资料与已知可用材料 | 不保证原味、经典身份或未经支持的等量比例 |
| 制作指导 | 用户不理解当前步骤 | {直接指导} → {必要操作条件} → {资料依据} | 当前配方与适用知识 | 关键条件未知时先问一项，不能编造数值 |
| 故障排查 | 用户描述实际异常 | {可能原因} → {对应已知事实} → {有依据的处理建议} → {限制与来源} | 用户确认的实际操作及资料 | 不把可能性写成确定诊断；证据不足就说明 |
| 知识解释 | 用户询问材料或技法 | {简短解释} → {适用范围} → {来源} | 支持当前论断的知识条目 | 不为展示专业性增加资料未支持的细节 |

追问只包含一个影响下一步判断的问题。例如：缺料项不明问“这杯缺少哪一种材料？”；用户已说清缺什么时不能重复问。两类候选澄清话术仅在 [候选规则](cocktail-agent-plan.md) 满足时展示。

## 三、固定状态话术（目标文案）

以下由应用根据已确认状态选择，不由模型自由编造错误原因。现有 `/ask` 的实现文案可能不同；新窗口已实现主要对应状态，固定措辞与资料生成内容分别展示。

| 状态／触发条件 | 展示话术 | 可用操作 |
| --- | --- | --- |
| 两类均有有效候选且未表偏好 | “想看经典酒还是便利店调酒？” | 展示“经典酒／便利店调酒”选择按钮，也支持文字回答；继续当前任务 |
| 匹配成功但零候选 | “现有酒库里暂时没找到符合这些材料的配方，可以去选酒页调整条件。” | 仅附有效选酒入口 |
| 知识检索成功但无相关资料 | “现有资料里暂时没有找到这个问题的相关依据。” | 允许补充问题，不假装查询失败 |
| 资料不足以支持精确比例 | “现有资料不足以确定这个替换比例，暂时不能给出准确用量。” | 展示已有可靠说明，不补比例 |
| 知识支持不足，非比例问题 | “现有资料还不足以确定这个问题的答案。” | 可展示已被支持的部分及其限制 |
| 查询超时或失败 | “这次资料查询没有完成，你可以重试。” | 保留问题，由用户重试 |
| 实验室已有编辑，即将替换 | “实验室里已有调配内容，要保留当前内容，还是替换为这次选择的材料？” | “保留当前内容”／“替换内容” |
| 页面动作失效 | “这个操作入口暂时不可用。” | 如有已校验的替代入口才展示 |
| 未登录 | “登录后可以使用助手。” | 使用现有登录入口 |
| 配额或并发受限 | “提问较频繁或已有问题处理中，请稍后再试。” | 不自动连续重试 |
| 用户取消 | “好的，先不继续处理。” | 清除待执行动作 |
| 超出产品范围 | “我可以帮你找调酒功能、查看酒单，或解答制作问题。” | 不自动跳转 |

孤立数字的澄清需结合实际上下文生成，例如“你说的30毫升，是哪一种材料的用量？”不能对所有数字机械套用材料问题。

## 四、生成前后校验与验收

生成前确认当前任务、输入事实和工具结果；生成后检查论断依据、材料用量、配方身份及动作目标。固定状态由真实结果触发，不能让模型自行宣称登录失效或查询成功。

验收时同时检查文字与实际行为：是否答非所问、是否重复追问、是否编造用量、按钮是否到达对应功能、引用是否支持论断。模板是展示规范，不以逐字一致判定动态回复通过。对应案例见 [验收文档](agent-verification.md) A03–A22。

## 连续对话修订（2026-09-16）

用户消息发送即上屏；等待提示不替换整段对话。缺料追问必须继承当前酒及上轮问题，单独材料名按补充回答处理；材料与当前配方不符时先说明并确认。标题展示实际酒名，不使用“当前酒款：当前酒款”。RAG不足时允许联网，结论标明来自联网资料并展开来源；联网未找到依据时不生成确定答案。
