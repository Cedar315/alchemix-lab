# 项目复盘与秋招介绍

## 一句话介绍

AlcheMix Lab 是面向家庭调饮新手的 AI 应用，把材料选酒、配方实验室、场景化助手和产品管理后台连接起来。关注的核心问题是：用户看完建议后，能否继续完成选酒或制作任务。

## 可以展示的设计取舍

| 问题 | 当前选择 | 代价或限制 |
| --- | --- | --- |
| 只聊天难以进入制作 | 真实酒单卡片与实验室材料交接 | 需维护配方身份和动作来源校验 |
| 用户表达灵活 | 单模型结合上下文选择六个工具 | 模型仍可能遗漏限制或重复追问 |
| 回答可能缺乏依据 | RAG、受限联网与来源展示 | 检索相关不等于证据充分 |
| AI 直接改草稿容易误操作 | 预览与用户点击确认 | 多一步操作，换来可控修改 |
| 调用成功不等于解决问题 | 技术日志、任务反馈与人工评测分开 | 无反馈任务不能计为成功 |

架构和工具定义统一见[架构设计](architecture.md)，指标定义见[管理后台](admin-console.md)。当前默认引擎已经从规则漏斗迁移到 AI SDK 工具循环，介绍项目时不要使用历史笔记中的“当前十个工具、单次路由”等表述。

## 演示顺序

1. 用手中材料寻找真实配方，查看候选仍需准备的材料。
2. 在酒单页面提出缺料问题，观察助手展示替代酒款。
3. 继续询问具体搭配，点击助手给出的实验室入口，检查材料和可编辑参考量。
4. 展示收藏或酒记，再以管理员身份查看单条评测、工具记录及人工评价。

演示前在自己的环境确认数据和服务可用。后台涉及真实运行数据时，应使用测试数据或完成脱敏。

## 简历表述参考

> 设计并实现面向家庭调饮场景的 AI 应用，整合材料选酒、配方实验室与流式助手；基于 AI SDK 实现六类工具调用，结合 RAG、材料来源校验和用户确认完成从建议到操作的衔接；建设管理后台与分层评测，区分工具执行、用户反馈和知识证据质量。

按本人实际承担的职责修改动词与贡献范围。没有可靠实验数据时不填写准确率、留存提升、降本比例或用户规模；测试通过数引用[最近验证](verification.md)，不要累计不同版本的报告。

## 失败案例与下一步

历史评测曾出现未知体积被精确化、引用结论扩大、忽略“不增加液体”限制及重复追问。保留原始失败材料用于复测，不能因工具返回成功就把它们计为答案正确。

下一步优先补充同版本多轮任务评测、证据忠实度人工标注和真实用户任务观察。当前缺少长期记忆、完整跨服务成本归集及可证明产品效果的对照实验。
