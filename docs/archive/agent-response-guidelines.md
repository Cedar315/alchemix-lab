# AI 回复内容与话术规范

> 历史记录：保留当时的设计、结果及限制，不代表当前实现。当前版本见 [文档导航](../README.md)。

更新：2026-09-20；状态：产品展示与话术规范，v2 已接入主路径；完整措辞仍以运行状态和证据为准。意图和工具选择以 [Agent 方案](cocktail-agent-plan.md) 为准，本文件只定义用户看到的内容。

## 一、回复目标与表达要求

让用户理解当前问题和下一步操作。先给与问题直接相关的内容，再补必要条件和依据。面向新手使用短句，解释必要术语，不增加角色扮演、拟人动作或主动开场消息。

按钮只能来自校验通过的页面能力或真实配方。纯回答不强行附按钮。用户未点击前不能写“已为你打开”；没有成功检索不能写“已查阅资料”。

## 二、动态内容展示模板

花括号表示业务数据或有证据的生成内容，不是固定答案、API 字段或允许模型猜测的占位信息。只有所需值存在且校验通过才显示对应内容；不得将未填占位符展示给用户。

| 回复类型 | 触发场景 | 展示顺序／模板 | 动态内容依据 | 异常规则 |
| --- | --- | --- | --- | --- |
| 操作咨询 | 用户不知道功能位置 | “可以在{功能名称}中{操作目的}。”＋按钮“{定位或打开功能}” | 真实页面能力与按钮标签 | 无有效目标则说明不可用，不造入口 |
| 搭配探索 | 用户询问材料混合风味 | “可以把{已确认材料}带到实验室查看搭配。”＋有效实验室按钮 | 用户材料及有效实验室动作 | 对话不编造精确用量；实验室可按明确匹配的材料库生成可编辑的参考量，必须说明是假设，不是实际倒入量或等量替换；已在实验室则定位已有操作 |
| 库内配方查找 | 已获得有效候选 | 沿用 App 酒库卡片，最多三张；显示{酒名}、{匹配原因}、{缺料提示，仅必要时}，点击展开酒单 | 匹配结果、真实材料、详情身份 | 不把缺料候选写成现在就能做 |
| 指定酒单 | 用户指定名称且已查到 | “找到{酒名}的酒单。”＋按钮“查看{酒名}” | 真实配方查找结果 | 未找到或名称多义时不猜链接 |
| 缺料：信息未齐 | 缺料项未知，或用户未提出替代候选且可用材料未知 | 先问“这杯缺少哪一种材料？”，必要时再问“你手边有哪些可用的材料？”；保留有效快捷按钮 | 当前酒、用户已确认的信息及页面能力 | 不重复问已知信息，不在追问前先给替代推荐 |
| 缺料：可以检索 | 已确认缺料与具体替代候选，或已确认可用材料 | 先查站内酒库与资料，不足再联网；{建议选项} → {适用条件} → {风味差异或限制} → {来源链接}，同时保留快捷入口 | 检索资料与用户提出的候选或可用材料 | 候选不等于用户已拥有；不保证原味、经典身份或未经支持的等量比例；未查到时不再次机械询问库存 |
| 制作指导 | 用户不理解当前步骤 | {直接指导} → {必要操作条件} → {资料依据} | 当前配方与适用知识 | 关键条件未知时先问一项，不能编造数值 |
| 故障排查 | 用户描述实际异常 | 先问未知的实际材料，再问实际操作；事实明确后先查站内资料，不足联网，展示{可能原因} → {补救建议} → {限制与来源链接} | 用户确认的实际操作及资料 | 已知不重复问；配方不等于实际操作；不把可能性写成确定诊断 |
| 知识解释 | 用户询问材料或技法 | {简短解释} → {适用范围} → {来源} | 支持当前论断的知识条目 | 不为展示专业性增加资料未支持的细节 |

追问只包含一个影响下一步判断的问题。例如：缺料项不明问“这杯缺少哪一种材料？”；用户已说清缺什么时不能重复问。两类候选澄清话术仅在 [候选规则](cocktail-agent-plan.md) 满足时展示。

## 三、固定状态话术（目标文案）

以下由应用根据已确认状态选择，不由模型自由编造错误原因。现有 `/ask` 的实现文案可能不同；新窗口已实现主要对应状态，固定措辞与资料生成内容分别展示。

| 状态／触发条件 | 展示话术 | 可用操作 |
| --- | --- | --- |
| 两类均有有效候选且未表偏好 | “想看经典酒还是便利店调酒？” | 展示“经典酒／便利店调酒”选择按钮，也支持文字回答；继续当前任务 |
| 匹配成功但零候选 | “现有酒库里暂时没找到符合这些材料的配方，可以去选酒页调整条件。” | 仅附有效选酒入口 |
| 知识检索成功但无相关资料 | “现有资料里暂时没有找到这个问题的相关依据。” | 允许补充问题，不假装查询失败 |
| 资料不足以支持精确比例 | “现有资料不足以确定这个替换比例，暂时不能给出准确用量。” | 展示已有可靠说明，不补比例 |
| 知识支持不足，非比例问题 | “现有资料还不足以确定这个问题的答案。” | 可展示已被支持的部分及其限制 |
| 查询超时或失败 | “这次资料查询没有完成，你可以重试。” | 保留问题，由用户重试 |
| 实验室已有编辑，即将替换 | “实验室里已有调配内容，要保留当前内容，还是替换为这次选择的材料？” | “保留当前内容”／“替换内容” |
| 页面动作失效 | “这个操作入口暂时不可用。” | 如有已校验的替代入口才展示 |
| 未登录 | “登录后可以使用助手。” | 使用现有登录入口 |
| 配额或并发受限 | “提问较频繁或已有问题处理中，请稍后再试。” | 不自动连续重试 |
| 用户取消 | “好的，先不继续处理。” | 清除待执行动作 |
| 超出产品范围 | “我可以帮你找调酒功能、查看酒单，或解答制作问题。” | 不自动跳转 |

孤立数字的澄清需结合实际上下文生成，例如“你说的30毫升，是哪一种材料的用量？”不能对所有数字机械套用材料问题。

## 四、生成前后校验与验收

生成前确认当前任务、输入事实和工具结果；生成后检查论断依据、材料用量、配方身份及动作目标。固定状态由真实结果触发，不能让模型自行宣称登录失效或查询成功。

验收时同时检查文字与实际行为：是否答非所问、是否重复追问、是否编造用量、按钮是否到达对应功能、引用是否支持论断。模板是展示规范，不以逐字一致判定动态回复通过。对应案例见 [验收文档](agent-verification.md) A03–A22。

## 连续对话修订（2026-09-16）

用户消息发送即上屏；等待提示不替换整段对话。缺料追问必须继承当前酒及上轮问题，单独材料名按补充回答处理；材料与当前配方不符时先说明并确认。标题展示实际酒名，不使用“当前酒款：当前酒款”。RAG不足时允许联网，结论标明来自联网资料并展开来源；联网未找到依据时不生成确定答案。

### 2026-09-22 验收修订

- 推荐、打开酒单与知识问答混合时，两项请求都需处理；知识部分提到的材料不视为用户库存。
- 新的独立知识问题保留用户问题范围，不能自行扩展成具体酒精数值、品牌或比例问题。
- 用户补充操作步骤时，保留前轮完整实际用料；明确纠正时才替换旧事实。
- 材料与操作已明确但检索不足时，说明证据不足，不机械要求再次补充同样信息。
- 提及摇和时长的故障问题仍须按实际材料检索，不直接套用乳饮分层说明。引用存在不代表论断有依据，生成后需核对支持范围。

## 配方核验与替换结果（2026-09-20）

- 核验便利店配方时使用详情页同源的完整材料行，包括冰块和可选配料；“适量”和装饰不换算成液体毫升，也不当作用户库存。
- 配方争议保存当前酒单、争议材料和用户指出的条目。收到纠正先重新核验：查到则承认并继续原问题；未查到则说明版本尚不一致，请求完整条目，不重复断言用户说错，也不把用户引用自动写成官方配方。
- “换柠檬汁是什么口感”需要提取材料槽位“柠檬汁”，整句话不得进入成分标签。替换对象不明时只问替换哪项，并保留新材料。
- 自动选材只使用明确名称或别名，不能用口味标签、配料表成分或模糊搜索分数替代材料身份。名称存在歧义时由用户选择，不能自动生成结果。
- 替换后的参考量、名称和风味全部按新材料重新计算。柠檬汁默认使用纯果汁条目时需明确提示；果汁饮料需选择实际产品。原茶饮已经移除时不得沿用茶属性。

### 2026-09-24 补救咨询试点

“倒多／加多”等补救咨询由模型结合当前酒单、用户原话和最近追问决定下一步，不再套用上表中故障排查的固定材料→操作顺序。材料已知而用量未知时，不重复询问材料；仅当缺失条件会改变建议时追问一个问题。模型可直接检索，也可先澄清，不要求首轮固定问混合状态或用量。

一般处理方向与精确补加量分开。用户不记得用量时可以检索不依赖精确数字的建议；资料不足说明限制，不要求重新提交全部信息。估计值保留不确定性，页面配方和助手建议均不能当作实际操作。实验室不再是补救咨询的固定终点。其他故障、缺料和导航流程本轮不变。

### 补救咨询的检索后决策

补救咨询获得 no_evidence / insufficient_evidence 后，可进行一次模型决策，选择一般指导、必要追问或明确限制，不自动重复检索。一般指导显示“一般调酒建议（未获本次检索证实）”，不进入引用结论列表，不伪造来源，也不触发页面写入。允许条件式基础建议；精确补加量、比例及安全保证不由此通道提供。用户原话、估计值和纠正保留在上下文中；搜索问题只包含用户描述，不拼接规则指令。检索服务失败仍作为技术错误处理。

补救回复展示前增加一次独立语义编辑，覆盖规划器直接追问与检索后一般指导：检查浓度/体积/酒精总量，明确分杯不等于稀释；结合已问过、已回答与未知条件避免重复追问。程序另对规范化后的相同问题兜底。语义编辑失败不展示未经编辑的一般指导；沿用原45秒单轮截止时间，不无限重试。编辑使用模型一般知识，不等同于来源核验或专业审核。

### 2026-09-25：搭配建议后的下一步（AI SDK 助手）

探索材料搭配时，先回答用户实际询问的口味，再自然追问还有哪些材料，并给出「去调配实验室」入口。已经说明完整材料或没有其他材料时不重复追问；不因当前配方页面而强行把问题解释成替换配方。

入口复用 `navigationTargets.lab`。搭配讨论时通过 `preview_lab_change` 准备当前材料，未指定用量则省略 amount；点击入口后复用旧版材料库匹配和默认参考量，可继续编辑。已有草稿须确认替换。只有纯导航且未讨论材料时使用空跳转。前端只将已注册地址渲染为操作按钮，其他模型生成地址仍显示为普通文字。

### 2026-09-25：材料入口与返回聊天（最新确认）

搭配建议必须在同轮结构化回复里携带 lab 操作，前端直接显示材料按钮，不再依赖模型生成 Markdown 链接或调用预览工具。按本次建议比例给具体毫升数；无比例时用材料库默认量。只带入当前讨论且来源可验证的材料，已有草稿须确认替换。入口打开可编辑材料列表。

从聊天点开酒单或实验室，目标页面左上角显示「← 返回聊天」，恢复记录、草稿与阅读位置，保留实验室编辑。常规浏览不显示。具体实现及验证见 `agent-material-return-2026-09-25.md`；本节取代上文纯跳转及只用工具预览的约定。

### 2026-09-26：缺料先选酒，再讨论替代材料

在具体酒单报告缺料时（如金酒西柚汽水页面说“没有西柚汽水了”），先按当前基酒查询真实酒库，排除缺料，展示候选酒卡及还需准备或确认的材料。本轮不展示实验室入口；页面基酒只作为查询方向，不等于已确认库存。无候选时说明结果并追问必要材料。

用户随后问“养乐多可以吗”等具体替代方案时，承接原酒款的基酒，回答风味和限制，再展示“我的酒精实验室”材料入口。带入原基酒与新替代材料，移除缺料；不擅自采用尚未选择的候选酒单。原基酒通过本轮真实酒单查询核验来源。此规则优先于此前缺料先问全量库存、材料变化立即给实验室入口的泛化约定。
