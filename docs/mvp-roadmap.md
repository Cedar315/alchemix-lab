# AlcheMix Lab MVP 开发路线图

## 这个文档是做什么的？

这份文档用来说明 **项目应该按什么顺序开发**。  
它回答的是执行层面的问题：

- 先做什么？
- 后做什么？
- 哪些功能属于 MVP？
- 哪些功能可以放到 2.0？
- 每个阶段完成后应该有什么结果？

如果你要安排开发计划、拆任务、看项目进度，就看这份文档。

---

## 阶段 1：基础环境和数据库

目标：  
把项目基础架子搭好，让前端、数据库、API 可以正常工作。

任务：

- [ ] 确认 Next.js App Router 正常运行
- [ ] 确认 Tailwind / CSS 样式生效
- [ ] 配置 Prisma
- [ ] 配置 Supabase PostgreSQL
- [ ] 建立核心数据表
- [ ] 建立本地 seed 数据
- [ ] 加入常见酒类、便利店饮料、果汁、茶饮、乳酸饮料
- [ ] 建立 drink_logs 表
- [ ] 建立用户基础表

完成标准：

- 本地能启动
- 页面不是裸 HTML
- Lab 能添加材料
- 本地数据库能查到材料

## 阶段 6：口味画像和推荐算法

目标：  
让系统越来越懂用户。

这一阶段是当前项目的重要后续能力。  
它不依赖 AI，可以先用本地数据和规则算法完成。

任务：

- [ ] 记录搜索行为
- [ ] 记录点击行为
- [ ] 记录 Lab 实验行为
- [ ] 读取 drink_logs 的真实评分
- [ ] 建立用户口味向量
- [ ] 建立配方风味向量
- [ ] 使用相似度计算推荐
- [ ] 加入时间衰减
- [ ] 加入探索机制，避免推荐过窄
- [ ] 在 My 页面展示动态口味画像
- [ ] 在 Assistant 和 Inspiration 中使用画像排序酒卡

推荐算法建议拆成这些文件：

```bash
src/lib/recommendation/
├── taste-profile.ts       # 根据用户行为生成口味画像
├── recipe-vector.ts       # 把酒卡/配方转成风味向量
├── scoring.ts             # 推荐分计算
├── event-weight.ts        # 搜索、点击、实验、收藏、已喝记录权重
└── explanation.ts         # 生成“为什么推荐这杯”的解释
```

推荐信号优先级：

1. 已喝评分和口味打分
2. 收藏和星标
3. Lab 实验材料
4. 点击酒卡
5. 搜索关键词

推荐算法原则：

- 搜索代表兴趣，不一定代表喜欢
- 已喝评分代表真实偏好
- 近期行为权重更高
- 高分酒的风味会增强画像
- 低分酒的风味会降低画像
- 80% 推荐熟悉口味，20% 探索相邻口味

完成标准：

- 口味画像不是静态展示
- 用户评分越多，推荐越准
- 搜索和实验也能影响画像
- 推荐结果可以解释原因

## 阶段 7：可选 AI 辅助层（MVP 后）

目标：  
在本地数据库无法覆盖时，用 AI 做候选补全和解释辅助。  
这一阶段不属于当前 MVP 必须完成范围，可以放到上线后或面试展示的下一步计划。

注意：

- 当前不做 AI Agent
- AI 是功能背后的辅助能力
- AI 不负责主导航和聊天界面
- AI 不直接写数据库
- AI 必须通过 Next.js API Route 调用
- AI 输出只作为候选草稿，事实数据仍以本地数据库和人工审核为准

任务：

- [ ] 可选接入 MiniMax API
- [ ] 设计统一 AI Route
- [ ] 写 Zod 输入输出校验
- [ ] 生成候选配方草稿
- [ ] 辅助经典酒改良解释
- [ ] 辅助风味解释
- [ ] 辅助命名
- [ ] 本地无结果时生成饮品资料候选草稿

完成标准：

- 本地数据库优先
- AI 不直接写数据库
- AI 输出必须结构化
- 失败时有 fallback
- 前端没有聊天 Agent 形态
- 用户感觉是在使用工具，而不是和机器人聊天
- 管理台可以看到 AI 候选草稿，并由人工确认后再入库
