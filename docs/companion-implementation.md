# 悬浮助手 v2 实现与验证

更新：2026-09-16。状态：本地代码已实现并进行分层验证，未部署生产。产品要求见 [PRD](prd.md)，本文件记录本轮实现及其实际边界。

## 一、已接入的用户流程

- 经典详情、便利店详情和实验室显示圆形入口；首页、浏览列表不显示。首页原“问问助手”卡改为浏览酒单，保留工作流优先。
- 手机底部抽屉默认约67%屏高，可展开／收起、拖动和键盘关闭；电脑预览也在手机页面容器内展开。首次进入只有当前背景与自由输入，不展示帮助分类菜单。
- 同页操作滚动定位并突出显示原功能；跨页只接受注册目的地或真实配方 ID。用户点击前不执行。
- 材料查酒复用首页目录与排序，最多三杯；两类都有候选且用户未表偏好时询问类别，支持按钮和文字回答。卡片点击展开真实材料与已有步骤，并保留完整详情入口。
- 缺料保持当前酒，依次确认缺料项和可用材料；实际故障依次确认实际材料和操作。结构化 pending 保存当前追问，已知事实不重复问；经典详情保留便利店改良入口。信息齐全后先查站内酒库与资料，不足再联网；酒库的其他搭配只能作为不同配方参考，不能证明等味等量替换。
- 实验室收到材料后进入待确认区，不自动填用量或立即分析。用户通过原材料选择与用量操作加入实验；有已有编辑时必须选择保留或替换。
- 仅在当前页面内存中保留本杯最多24条消息，向服务端发送取消之后的最近12条。收起保留，换杯、离页或刷新清空；跳转实验室后按实验室当前内容开启新对话。
- 任务 ID 和背景版本共同校验迟到回复及旧动作。登录身份变化时清除旧会话；未登录可以保留当前输入，但服务端拒绝问答调用。

## 二、工作流复用映射

| 页面／能力 | 实际数据与逻辑 | 身份／操作目标 |
| --- | --- | --- |
| 首页选酒 | [explore-catalog.ts](../src/lib/data/explore-catalog.ts) 的 BEGINNER_CATALOG；[beginner.ts](../src/lib/recommendations/beginner.ts) 的 matchDrinks | 维持原筛选与排序，页面不再作为后端目录依赖 |
| 经典酒详情 | 同一模块的 classicExploreCocktails、CLASSIC_DATABASE | `/inspiration/classic-remix?cocktail=…`，通过标准化 ID 匹配 |
| 便利店详情 | convenienceExploreCocktails、getConvenienceRecipeGuide | `/inspiration/convenience-mix?cocktail=…` |
| 助手材料匹配 | [workflow-catalog.ts](../src/lib/agent/workflow-catalog.ts) 调 matchDrinks 后校验必要材料 | 经典候选必须有显式配方；材料齐全的候选排前，至少匹配两种且只缺一种时可作为接近选择展示，并明确缺料 |
| 经典改良／步骤定位 | 现有详情控件 | 固定 capability → DOM 目标映射，模型不生成选择器 |
| 实验室交接 | LabScreen 原材料检索、用量选择与加入逻辑 | sessionStorage 临时交接，5分钟有效；空缺用量由用户确认 |
| 制作知识 | 现有 RAG runtime | 保留来源、适用范围、无证据与技术失败的区别 |

2026-09-14 的目录基线为首页328项、经典详情286项、便利店详情352项；当时显式经典配方18项。本轮为嗨棒和帕洛玛补充独立、有来源的详情，并移除跨酒款错误别名。差异来自首页支持范围和经典显式配方约束，不是另一套人工六杯目录。这些数量说明数据覆盖，不代表所有配方内容已通过专业审核。

未核实的经典条目只展示对应名称、材料和简介，不再生成占位用量或回退到其他酒。材料齐全不等于库存量足够；知识审核新增数据库表，未增加库存表。

## 三、接口、模型与恢复

`POST /api/agent` 用 `version:2` 区分新请求，原 `/ask` 和无 version 请求继续使用 v1。严格输入／输出契约、登录、共享配额及45秒截止时间继续生效，见 [服务设计](ai-service-design.md)。

v2 使用一次模型意图识别，非法协议最多修复一次；明确取消和类别回答可直接处理。针对“打开指定酒单”“已命名材料搭配风味”“明确已有材料”的表达，采用目录内实体规则校正已观察到的模型偏差。未知自然语言仍由模型识别，规则不生成酒单或替代知识。

知识事项先调用一次现有 RAG，证据不足时最多联网搜索一次并基于正文回答，自动收集待审核知识；正式发布与索引规则见[知识闭环](knowledge-learning.md)。混合请求保留可用的配方／操作结果并单独呈现检索失败。新 v2 不复制旧版容量计算器；不承诺任意精确换算。

实验室草稿仍在本标签页暂存，对话只保留在当前页面内存中；同杯收起保留，离开、换杯或刷新清空。没有用户点击不会写酒记、评分或修改库存。详细运行命令见 [后端手册](backend-operations.md)。

## 六、本轮修正与验收边界

- 帕洛玛错误别名曾指向玛格丽特；嗨棒的 highball ID 曾无法匹配并回退内格罗尼。现已修正，卡片、详情与助手一致。嗨棒按[Suntory](https://house.suntory.com/cocktails/whisky-highball)比例示例，帕洛玛按[IBA](https://iba-world.com/iba-cocktail/paloma/)配方。
- 发现页初始状态始终为“从一杯开始”；上次结果由用户主动打开。浏览器检查覆盖两个推荐详情返回以及自由调配、找酒谱、我的三个栏目返回。
- 用户消息发送即显示，输入框清空；等待与回复进入聊天流，失败支持重试。桌面与手机都在应用容器内展示。
- 连续缺料追问绑定当前酒，单独回答材料名能衔接；材料不属于配方时确认不一致。降低酒感不会落入“找哪个功能”的无效追问。
- 相似酒从同一目录按口味标签/材料交集排序，不生成新酒谱，不把相似当成库存齐全。
- 审核权限、联网故障、可信域名过滤、虚构引用拒绝、精确去重、过期修订拒绝、撤回与审计均有针对性验证；模拟用例不等同真实联网或真实管理员浏览器验收。
